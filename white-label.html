Capacitor Auth Manager, published under your name

Your app teams install your package, read docs on your domain and file issues with you. We rename the package across npm, iOS and Android, publish each release under your scope and keep it in step with capacitor-auth-manager. The code stays MIT. What you pay for is that work, and the right to say your package is built on Capacitor Auth Manager, logo included.

What changes in your build

Four platforms carry the package’s name, so a rebrand touches four places, plus the import line in every app. We make these changes once, then carry them into every release.

The API doesn’t change. auth.signIn(AuthProvider.GOOGLE) returns the same credential, and your build has the same providers as the release it’s built from. In 3.x that’s Google on web, iOS and Android.

A managed build, for a team called Acme
  // package.json
- "name": "capacitor-auth-manager"
+ "name": "@acme/sign-in"
  // CapacitorAuthManager.podspec
- s.name = 'CapacitorAuthManager'
+ s.name = 'AcmeSignIn'
  // android/build.gradle
- namespace = "com.aoneahsan.capacitor_auth_manager"
+ namespace = "com.acme.sign_in"
  // src/capacitor-plugin.ts
- registerPlugin('CapacitorAuthManager', …)
+ registerPlugin('AcmeSignIn', …)
  // your app
- import { auth, AuthProvider } from 'capacitor-auth-manager';
+ import { auth, AuthProvider } from '@acme/sign-in';

What we run for you

Publishing under your scope

Each release goes to npm as your package, with your name in the README, the package metadata and the changelog.

Every upstream release, carried over

When capacitor-auth-manager ships a patch, a feature or a major, we apply your rename to it and check the packed tarball, not only the source tree, before it goes out.

Docs on your domain

This documentation, rebranded to your package name and logo, hosted on a domain you choose.

The name and the logo

The right to say your package is built on Capacitor Auth Manager and to show its logo. The MIT license doesn’t grant that.

A license anyone can check

Your docs domain serves a license file, and anyone can confirm it on the verify page.

One contact for changes

Work only your apps need, from an earlier provider to a different credential handoff, is quoted separately.

The code is already yours to fork

Anyone can fork capacitor-auth-manager and publish it under another name today. The MIT license allows it. A license makes sense when you’d rather not own that fork: four platforms’ identifiers on every release, Google’s SDK changes, and docs that keep up.

The source is already open, so there’s no buyout, and a license isn’t exclusive. We may license the package to other teams too.

Questions

Do we get the source code?

It’s already public under MIT on GitHub. The license covers our work on your build and the right to the name and logo.

Which providers does our build include?

The same as the upstream release it’s built from. In 3.x that’s Google on web, iOS and Android.

Is the license exclusive?

No. We may license the package to other teams.

What happens after the included months?

The versions already published under your name stay on npm and keep working. New releases need a renewal.

How does someone check our license?

By your license key or your docs domain, on the verify page.
